markitdown vs markitdown-rs

markitdown-rs is a markitdown alternative that keeps markitdown's output: Microsoft's markitdown rewritten in Rust as one binary, plus a Python package with the same API. Here is how it compares with markitdown itself and with the other tools people use to turn documents into Markdown for LLMs. Repository numbers were read from the GitHub and crates.io APIs on 2026-10-22; behaviour was checked by running each tool where possible, otherwise taken from its README (marked README).

When to use which

  • You call markitdown from a shell, CI job, container, agent (MCP) or Python code and want the same Markdown without markitdown's dependency stack: markitdown-rs.
  • You need OCR, LLM captions, Azure or plugins: Python markitdown, or markitdown-rs's Python package, which runs them on the Rust converters (or MDFlux for a desktop app with OCR).
  • You need layout-model PDF parsing, many more formats or bindings in other languages, and do not need markitdown's exact output: xberg.

Method

  • Stars and dates: gh api repos/<owner>/<repo> and /releases/latest, crates.io API, 2026-10-22.
  • Parity: cargo test in the markitdown-rs repository; for the crates.io crate, the same fixtures through its CLI against the same snapshots.
  • Speed: 231 Apache Tika and arXiv files outside the test set (2026-11-05), and scripts/bench.sh; numbers in the README.
